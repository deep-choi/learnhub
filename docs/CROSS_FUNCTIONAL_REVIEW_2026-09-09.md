# LearnHub 직군별 제품 검토와 출시 판단

기준: 2026-09-09 로컬 코드와 프로젝트 문서. 화면 검증·실제 AI 품질 평가·보안 침투 테스트·배포 환경 점검은 하지 않았다. 기존 UX 수정은 GPT-5.6 Luna High 3명이 담당하고, 이 문서는 총괄의 제품·직군별 검토다. 아래 제안은 확정된 사업 전략이나 사용자 조사 결과가 아니다.

## 1. 가장 먼저 결정할 제품의 범위

현재 세 가지 방향이 섞여 있다.

- `metadata.json`: 무엇이든 배우는 범용 AI 맞춤 학습.
- `docs/design_system_and_wireframes.md`: 연구자·엔지니어·자율적인 성인 학습자를 위한 지식 작업 공간.
- `src/data/initialData.ts`, `PlacementTestModal.tsx`: 초·중·고 수학과 3문항 수준 진단.

이것은 단순한 문구 차이가 아니다. 설명 난이도, 진단 문항, 학습 효과의 정의, 보호·지원 정책, 모바일 입력 방식까지 영향을 준다. 먼저 하나의 대표 사용 상황을 정해야 한다.

사용자 결정: 첫 출시의 핵심 대상은 **여러 분야를 배우는 일반 성인**이다. 따라서 수학 기초 재학습으로 서비스를 좁히지 않는다. 공통 입구는 주제·목적·사전 지식·가용 시간이며, 수학 진단은 선택적인 과목별 기능이다. 교과 학년을 전 분야의 수준으로 쓰지 않는다.

제품의 중심 약속 제안: '배우고 싶은 주제를 작은 학습 계획으로 나누고, 설명·연습·복습으로 이어갈 수 있게 돕는다.' 검증되지 않은 '무엇이든 완벽하게 가르친다'는 약속과 구분한다. 직무 활용·취미·교양·시험 준비 중 목적을 선택할 수 있어야 하지만 입력은 주제 하나로도 시작 가능하게 유지한다.

범용 학습이라고 모든 분야를 같은 퀴즈로 평가하지 않는다. 수학은 수치·수식, 언어는 표현·문맥, 프로그래밍은 코드·실행 결과, 교양은 설명·적용 능력이라는 차이를 지원 범위와 분리해 정의한다. 현재 코드 실행기·발음 평가기가 구현되지 않았다면 텍스트 예시와 자기 점검까지만 제공한다고 명시한다. 프레임워크 교체나 새로운 평가 엔진은 이번 수정에 자동 포함하지 않는다.

보안·개인정보 항목은 저장소 범위의 설계 검토이며 법률 준수나 실제 서비스의 안전성을 보증하지 않는다. 아동을 핵심 대상으로 삼는 경우의 구체적인 정책·법적 검토는 대상 지역과 연령을 정한 후 전문 담당자와 확인한다. 관찰되지 않은 운영 시스템이 외부에 있을 가능성도 열어둔다.

## 3. 문서와 구현의 차이

`TECH_SPEC.md`는 Next.js·Supabase·React Native·지식 추적 모델을 선정한 것처럼 설명한다. 현재 `package.json`, `server.ts`, `storage.ts`에서 확인한 실행 구조는 React/Vite·Express·localStorage다.

따라서 기술 명세의 내용을 '구현 완료'로 인수인계하거나, 명세를 맞추기 위해 즉시 플랫폼을 갈아엎으면 안 된다. 문서별로 현재 구현 / 제안 / 미결정 상태를 붙인 뒤 필요한 기능에 따라 변경 결정을 내려야 한다. 기존 기술 명세는 이번 검토에서 덮어쓰지 않았다.

## 4. 제품·학습·운영의 성공 기준 제안

아래는 목표 수치가 아닌 측정 정의다. 임의의 전환율이나 정확도를 현재 성과로 제시하지 않는다.

| 지표 | 정의 | 오해를 막는 구분 |
|---|---|---|
| 첫 학습 진입 | 첫 방문 세션 중 첫 레슨 본문을 연 비율 | 샘플 방문과 개인 과목 생성을 분리 |
| 첫 문제 시도 | 레슨 진입 중 유효한 답안을 한 번 제출한 비율 | 힌트 클릭·빈 제출·중복 요청 제외 |
| 학습 종료 | 읽기 또는 풀이를 마치고 사용자가 종료한 세션 | 정답률이나 이해도와 동일시하지 않음 |
| 중단 복구 | 저장한 레슨·답안·메모가 다음 진입에서 복원된 비율 | 로컬 새로고침과 다른 기기 동기화 분리 |
| 학습 효과 | 같은 개념의 다른 문항에서 정답·설명 수준이 나아지는지 | 같은 답 외우기·힌트 후 정답과 독립 수행 구분 |
| 복습 이행 | 실제 예약된 문항 중 예정일 이후 유효하게 시도한 비율 | 큐 생성 문구만 노출한 경우는 예약으로 세지 않음 |
| AI 품질 | 유효한 형식, 올바른 내용, 적절한 난이도, 응답 지연 | HTTP 성공을 콘텐츠 정답으로 해석하지 않음 |
| 운영 비용 | 유효하게 종료한 학습 1회당 호출 수·입출력 사용량·재시도 | 세션당 비용을 측정하기 전 무제한 약속 금지 |

## 5. 담당 구성

초기 단계에서 직군마다 한 명씩 채용할 필요는 없다. 다만 책임이 사라지면 안 된다.

- 제품 담당: PM + 서비스 기획 + 초기 사용자 조사. 누가 왜 사용하는지 결정한다.
- 경험 담당: 프로덕트 디자이너 + UX 라이팅 + 접근성 기준. 중요한 동작을 이해하고 수행할 수 있게 한다.
- 구현 담당: 프론트엔드 + 백엔드 + AI 연동. 저장·채점·복구를 실제 동작으로 만든다.
- 품질 담당: 교과 전문가의 내용 검수 + QA의 재현 가능한 검증. 설명이 맞는지와 서비스가 작동하는지를 각각 판단한다.
- 공개 운영 전: 보안·개인정보·인프라·고객지원 책임자를 정한다. 전담 채용 대신 검토/외부 협업으로 시작할 수 있다.

그래픽 디자이너의 삽화·브랜드 작업은 어려운 개념을 설명하거나 신뢰를 전달할 때 가치가 있다. 현재는 로그인·기록·정답 판정의 신뢰성과 학습 목표 연결보다 우선하지 않는다.

## 6. 이번 수정과 후속 과제의 경계

이번 코드 수정: 잘못된 계정/저장 약속 제거, 초기화 범위 제한, 과목 생성의 실패·취소, 잘못된 대체 레슨 제거, 채점 보류와 중복 제출, 완료·복습의 실제 저장 연결, 통계 표현·키보드/모바일 구조의 일부 개선. 상세 완료 상태는 작업 종료 시 아래에 기록한다.

후속 결정·구현: 실제 인증/클라우드 저장, 계정 병합·기기 동기화, 일반 성인의 우선 학습 분야와 대표 사용 상황 검증, 분야별 과정·진단·평가 기준, 콘텐츠 검수 및 오류 신고 운영, 공개 AI API 보호·비용 제한, 앱 출시.

사용자 검증: 실제 화면·좁은 화면·키보드·수식·AI 성공/실패·새로고침·학습 종료·복습 재방문. 자동 검사만으로 통과 처리하지 않는다.

- `node --import tsx --test tests/answerComparison.test.ts tests/review.test.ts tests/storage.test.ts`: 18개 통과, 실패 0개. 채점 비교 4개·복습 헬퍼 4개·저장 10개. 저장 실패 로그는 테스트가 의도적으로 재현한 오류이며 테스트 실패가 아니다.
- `npm run build`: Vite 프런트엔드와 esbuild 서버 빌드 모두 통과. 첫 빌드의 상위 디렉터리 읽기 권한 오류는 승인된 권한 경로에서 같은 명령을 재실행해 해결했으며, 코드 오류로 분류하지 않는다.

사용자에게 권하는 우선 수동 확인은 다음 여섯 가지다.

1. 일반 주제로 과목을 만들고, 생성 중 닫기·재생성이 자연스러운지 확인.
2. 힌트 → 오답 → 재도전과 분수/소수 답안을 확인. AI 장애는 테스트 환경에서 재현하고 오답 기록 여부 확인.
3. 서로 다른 레슨에서 튜터 질문과 후속 질문을 해보고 인용문·대화가 섞이지 않는지 확인.
4. 메모·손글씨 작성 후 닫기·새로고침·다른 레슨 이동을 거쳐 저장 범위를 확인.
5. 레슨 완료 → 홈 → 첫 미완료 레슨 진입, 다음 날 복습·오답 재예약·추가 생성 문항 보존 확인.
6. 휴대전화 폭·키보드만 사용·200% 확대에서 위 흐름과 표/모달 접근을 확인.

## 8. 일반 성인·다분야 기준의 첫 콘텐츠 검증 묶음

각 주제에서 새 과목 생성 → 레슨 → 질문 → 연습 → 종료 → 복습을 사용자 검증으로 진행한다. 실제 AI 호출을 이번 총괄 검토에서 수행하지 않았으며 아래는 합격 기준이다.

| 입력 사례 | 사용자 목적 | 분야에 맞는 결과 | 실패로 볼 결과 |
|---|---|---|---|
| 파이썬 반복문, 초보, 하루 10분 | 간단한 반복 작업 이해 | 짧은 코드와 실행 결과 설명, 코드 필드 표시, 실행 지원 여부 명시 | 코드가 누락되거나 실제 실행하지 않고 실행 성공이라고 표시 |
| 여행 일본어, 카페 주문 | 짧은 상황 대화 연습 | 대화 예시·표현의 맥락·다른 허용 표현, 음성 기능 지원 범위 안내 | 문자열이 다르다는 이유로 유효 표현을 무조건 오답 처리하거나 발음 평가를 했다고 표시 |
| 사진의 조리개와 노출 | 직접 촬영에 적용 | 상황별 결과 예측과 안전한 실습 과제, 자기 점검 기준 | 수학 문제만 반복하거나 실습 수행을 확인하지 않고 숙련 판정 |
| 인상주의 미술 입문 | 작품 감상에 활용 | 특징·비교·자기 언어로 설명하는 활동, 확인 가능한 사실과 해석 구분 | 존재하지 않는 작품·작가 관계를 사실로 단정하거나 출처를 지어냄 |
| 분수와 비율 다시 배우기 | 일상 계산 이해 | 쉬운 예시, 수식 표시, 1/2와 0.5 동치 처리 | 생성 실패 때 미적분으로 바뀌거나 채점 장애를 오답 기록 |

내용 품질은 분야별 검수자가 확인한다. 사용자 한 사람의 화면 검증이나 TypeScript 검사만으로 각 분야의 정확성을 인증하지 않는다. 분야 확장은 '주제 입력 가능'과 '신뢰할 수 있게 가르칠 수 있음'을 별도로 기록한다.
