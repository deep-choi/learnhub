# LearnHub 관리자 운영

## 접속과 권한

- 주소: 서비스 도메인의 `/admin`.
- 관리자 계정은 학습 화면의 설정 → 계정에서도 `운영 콘솔 열기`로 이동할 수 있다. 일반 계정에는 표시하지 않는다.
- LearnHub의 기존 Firebase 로그인 사용. 서버는 매 요청마다 서명과 토큰 취소 여부를 검증하고 `admin: true` custom claim 또는 `LEARNHUB_ADMIN_UIDS`의 UID를 확인한다.
- 로그인하지 않은 요청은 401, 일반 계정은 403. 로컬 접속이나 개발 모드에도 관리자 우회 권한은 없다. 관리자 응답은 `Cache-Control: no-store`다.
- 브라우저 Firestore 접근은 기존 deny 규칙 유지. 관리자 데이터도 서버 API에서만 접근한다.

권한 부여는 운영자의 실제 로그인 이메일을 확인한 뒤, 해당 프로젝트를 관리할 Application Default Credentials가 있는 환경에서 실행한다. 비밀키를 저장소에 추가하지 않는다.

```powershell
npm run admin:access -- --email "실제로그인이메일"
```

기존 custom claim은 보존한다. 권한 변경 후 `/admin`을 새로고침하거나 ‘다시 확인’을 누르면 최신 토큰으로 권한을 재확인한다. ADC가 없다면 Google Cloud SDK에서 `gcloud auth application-default login`으로 운영 계정 인증이 필요하다. Firebase CLI 로그인만으로 Admin SDK의 ADC가 준비되는 것은 아니다.

권한 해제:

```powershell
npm run admin:access -- --email "실제로그인이메일" --revoke
```

해제 시 refresh token도 취소한다. UID allowlist도 사용하는 계정이라면 서버 환경의 해당 UID를 함께 제거해야 한다.

## 제공하는 기능

| 메뉴 | 기능 |
| --- | --- |
| 운영 현황 | 사용자 수(1,000명 초과는 1,000+ 표시), 당일 승인된 AI 요청·예약 토큰·공급자 보고 토큰·처리 실패·평균 응답시간, 최근 오류 10건 |
| AI 운영 | 생성 일시 중지, 모델별 사용 중지, 일일 제한 적용 여부, 계정별/전체 일일 요청·출력 예약 한도 변경 |
| 사용자 | 25명씩 조회, 정확한 이메일/UID 검색, 당일 요청·예약 토큰·최근 로그인·클라우드 저장 메타데이터, AI 이용 제한/해제 |
| 신고 | 기존 계정별 신고까지 모아서 25건씩 조회, 접수/검토 중/처리 완료와 운영 메모 저장 |
| 결제·환불 | 미연동 상태와 예정 관리 항목 표시. 실제 결제·환불 버튼/API 없음 |
| 변경 이력 | 최근 50건의 설정/계정 AI 권한/신고 처리 변경 전후 값, 운영자 UID와 시각 |

계정 이용 제한은 AI 생성에 적용한다. 로그인·기존 수업과 기록 열람은 유지한다. 자기 계정과 다른 관리자 계정은 AI 제한할 수 없다. 전체 사용자 학습 원문이나 인증 비밀값을 목록에 노출하지 않는다.

## 설정과 사용량의 의미

- 설정 문서는 기존 `learnhubConfig/aiQuotaPolicy`를 확장한다. 기존 requestLimit/outputTokenLimit은 유지하고 없는 필드만 서버 기본값으로 보완한다.
- 설정은 매 공급자 호출에서 다시 읽는다. 별도 배포 없이 다음 검사부터 반영된다. 이미 시작한 공급자 요청은 취소하지 않는다.
- 요청 차단은 공통 AI gateway에서 검사하므로 로그인 전 체험·미리보기·자료/음성 처리에도 적용된다.
- 모델 중지는 해당 모델 요청을 거절한다. 기본 모델을 중지하면 기본 모델을 사용하는 체험에도 영향을 줄 수 있으므로, 전체 생성 중지와 구분해 적용한다.
- 기존 프로세스 메모리의 전체 일일 한도를 대체해 `learnhubOperationsDays/{UTC-date}`에 전체 한도를 transaction으로 예약한다. 서버 재시작/다중 인스턴스에서도 공유한다. 동시성·분당 제한과 비로그인 체험의 별도 한도는 유지한다.
- 사용자 일일 한도는 기존 `learnhubUsers/{uid}/aiUsage/{UTC-date}`를 계속 사용한다. 전체 예약과 계정 예약은 별도 단계이므로 실패한 시도의 예약이 남을 수 있다. 예약량은 실제 청구량이 아니며 실패/차단 시 자동 환급하지 않는 보수적 한도다.
- 날짜 기준은 UTC 자정, 한국 시간 오전 9시다.
- 출력 예약 토큰은 입력 토큰·모델별 단가·캐시·기타 인프라 청구를 포괄하지 않는다. 금액 상한이나 청구액으로 표시하지 않는다.
- AI 결과 지표는 도입 이후부터 기록한다. 공급자가 사용량을 반환하지 않으면 실제 토큰은 집계할 수 없다. 지표 쓰기는 응답 전 완료를 기다리지만 저장 실패 시 AI 응답은 유지하고 `ai_metrics_write_failed` 로그를 남기므로 누락 가능성이 있다.
- AI 오류에는 기능/모델/상태/요청 ID/지연시간만 저장한다. 프롬프트·학습 답안·토큰·공급자 오류 객체를 저장하지 않는다. 최근 오류는 30일 TTL이며 Firestore TTL 삭제는 즉시 보장되지 않는다.
- 수정과 변경 이력은 같은 transaction에 저장한다. 설정과 신고는 revision으로 동시 편집을 감지한다. 현재 화면에서 과거 설정 자동 복원 기능은 제공하지 않는다.

## 배포와 확인

Hosting과 Functions, 신고 목록의 collection-group 인덱스를 함께 배포한다.

```powershell
npm run deploy:firebase -- --project learnhub-1de94 --non-interactive
```

`firestore.indexes.json`에는 `contentReports.createdAt`의 collection-group 정렬 인덱스와 오류 TTL 설정이 있다. 인덱스 준비 전 신고 조회가 실패하면 준비 완료 후 재시도한다. 최초 배포 이후에도 기존 신고는 추가 이관 없이 조회된다.

실제 배포 후 확인할 항목:

1. 로그인 전 `/api/admin/settings`는 401, 일반 계정은 403.
2. 운영자 로그인 후 사용자·신고·설정이 실제 데이터로 조회됨.
3. 일시 중지 저장 후 일반 계정·비로그인 체험에서 새로운 AI 생성이 거절되고 기존 기록은 열람됨.
4. 생성 재개 후 다시 호출됨. 한도를 낮춘 뒤 초과 요청이 거절됨.
5. 신고 상태와 운영 메모가 새로고침 후 유지되고 변경 이력이 남음.

로컬 자동 테스트는 Firebase 운영 데이터·실제 관리자 계정·실제 AI 공급자 호출 검증을 대신하지 않는다.

## 후속 작업

자동 이메일 알림, 서버 측 학습 성과 집계, DB 자동 백업/복원, 점검 공지, 모델별 품질 평가 화면, 사용자별 임시 한도 예외, 관리자 내 권한 관리는 이번 버전에 포함하지 않는다. 백업과 청구 알림은 외부 콘솔의 실제 상태를 확인해 별도로 설정한다. 결제 설계는 `BILLING_AND_REFUNDS.md` 참고.
