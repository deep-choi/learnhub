# LearnHub UX 기획 및 사용자 검증 계획

작성 기준: 2026-09-09 현재 소스. 총괄: 메인 에이전트. 분담: GPT-5.6 Luna / High 서브에이전트 3명. 화면·기기·실서비스 검증: 사용자.

후속 결정: 사용자가 첫 출시 대상으로 '여러 분야를 배우는 일반 성인'을 선택했다. 아래 페르소나와 백로그는 수정 전 검토 기록이며, 실제 수정 상태와 확정된 제품 방향은 [직군별 검토](./CROSS_FUNCTIONAL_REVIEW_2026-09-09.md)를 우선한다. 수학 중심 방향과 아동 페르소나는 초기 가설/확장 시나리오이며 현재 주력 대상이 아니다.

이 문서의 페르소나는 실제 인터뷰로 검증된 이용자가 아닌 설계 가설이다. 소스에서 확인한 동작과 사용자에게 권하는 설계를 구분한다. 이번 작업은 기획이며 제품 코드 변경, 브라우저 조작, 실제 계정·AI 호출 테스트를 포함하지 않는다. 이전 대화의 화면 검토 결과는 현재 구현 증거로 재사용하지 않는다.

## 1. 기획 방향과 책임

현재 노출되는 수학 중심 학습을 우선 설계한다. 제품 설명의 범용 학습을 유지한다면 언어·코딩 과목에도 동일한 흐름이 성립하는지 별도 검증해야 한다. 음성 평가·코드 실행기를 이번 기본 범위에 자동으로 추가하지 않는다.

사용자가 각 화면에서 알아야 할 것은 네 가지다: 지금 무엇을 배우는지, 무엇을 하면 되는지, 어디까지 저장됐는지, 다음에 무엇을 할지.

| 책임 | 수행 내용 | 완료 기준 |
|---|---|---|
| 총괄 기획 | 페르소나·여정·정책·우선순위·충돌 조정 | 모든 핵심 요구사항에 확인 가능한 합격 기준이 있음 |
| Luna High A | 첫 방문·게스트·계정·온보딩·커리큘럼 소스 검토 | 근거 위치와 사용자 시나리오 제출 |
| Luna High B | 레슨·채점·튜터·메모 소스 검토 | 실패·재시도·중단 상황 포함 |
| Luna High C | 완료·복습·통계·이동 소스 검토 | 저장·재방문·기기 전환 상황 포함 |
| 사용자 | 실제 화면과 서비스 검증, 제품 의사결정 | 아래 체크리스트에 통과/실패/보류와 관찰 결과 기록 |

우선순위: P0는 기록·인증·콘텐츠·채점 신뢰를 해치는 출시 차단 문제, P1은 주요 학습 흐름의 불편, P2는 편의 개선이다. 시각적 취향만으로 우선순위를 정하지 않는다. 코드 수정과 출시 여부는 후속 작업이다.

## 2. 페르소나 10명

### P01. 가입 전 가치를 확인하고 싶은 첫 방문자 — 지우

- 목적: 나에게 도움이 되는지 2분 안에 판단한다.
- 여정: 첫 방문 → 샘플 체험 → 첫 문제 → 결과 확인 → 기록을 보관하기 위해 가입.
- 예상 불편: 시작부터 메뉴가 많음, 내 기록처럼 보이는 샘플 점수, 가입 이점 불명확, 로그인 후 체험 기록 소실.
- 필요한 UX: 샘플과 내 기록 구분, 대표 행동 하나, 로그인 없이 체험, 가입 후 기존 학습을 이어갈 위치 복원.
- 합격 기준: 사용자 설명 없이 샘플을 시작하고, 로그인 후 같은 레슨·답안·메모를 찾을 수 있다. 샘플 성적이 개인 성적에 섞이지 않는다.

### P02. 긴 문장과 학습 용어가 어려운 초등 학습자 — 민서

- 목적: 분수를 왜 통분하는지 이해한다.
- 여정: 보호자와 시작 → 초등 분수 선택 → 짧은 설명·예시 → 문제 → 이해한 것 확인.
- 예상 불편: '인지 수준', '결손', '소크라틱' 같은 용어, 긴 문장, 어려운 과목 추천, 작은 조작 영역.
- 필요한 UX: 쉬운 문구, 한 번에 한 개념, 구체적 예시, '잘 모르겠어요', 학습 주제에 맞는 힌트.
- 합격 기준: '분수' 수업에 미분 관련 고정 문구가 나오지 않는다. 문제를 모를 때 무작위 답을 고르지 않아도 도움을 받을 수 있다.

### P03. 기초가 약하고 틀리는 것을 두려워하는 중학생 — 준호

- 목적: 방정식에서 막히는 부분만 찾아 다시 배운다.
- 여정: 간단 진단 → 약한 개념 확인 → 보충 설명 → 오답 → 힌트 → 유사 문제 성공.
- 예상 불편: 3문항 점수만으로 학년을 단정, 오답을 능력 부족으로 표현, 정답만 제시, 계속 낮아지는 수치.
- 필요한 UX: 문항별 추천 근거, 진단 건너뛰기, 틀린 이유의 구체적 설명, 다시 풀기, 이전보다 나아진 부분 표시.
- 합격 기준: 같은 총점이어도 틀린 개념에 따라 추천이 달라진다. 오답 뒤 다음 행동이 있고 추천 수준을 직접 바꿀 수 있다.

### P04. 시험 범위와 마감이 정해진 고등학생 — 서연

- 목적: 시험 전 미분 문제 중 약한 유형을 집중 학습한다.
- 여정: 시험 목적·범위 선택 → 계획 검토 → 필요한 레슨만 학습 → 문제 재도전 → 남은 범위 확인.
- 예상 불편: 불필요한 챕터 생성, 목표를 수정할 수 없음, 모든 문제를 같은 중요도로 추천, 하루 계획과 실제 시간 불일치.
- 필요한 UX: 범위·목표 설정, 커리큘럼 미리보기와 제외, 개념별 문제 재도전, 남은 학습량 안내.
- 합격 기준: 관련 없는 단원을 제외하고 시작할 수 있다. 완료 화면에서 시험 범위의 남은 부분과 다음 권장 학습을 알 수 있다.

### P05. 이미 아는 부분을 건너뛰고 싶은 대학생 — 태윤

- 목적: 선형대수의 특정 개념을 깊게 이해한다.
- 여정: 정확한 개념 검색 → 선수 개념 확인 → 증명 읽기 → 심화 질문 → 연습 → 메모 보관.
- 예상 불편: 제목과 다른 레슨 이동, 고정된 미적분 예시, 기초 과정 강제, 수식·코드 표시 오류.
- 필요한 UX: 개념으로 직접 이동, 추천 이유, 깊이 조절, 수식이 포함된 해설, 참고 근거와 오류 제보.
- 합격 기준: 검색·지식 지도에서 선택한 개념과 실제 레슨 제목·본문이 일치한다. 필요한 수식을 정상적으로 읽을 수 있다.

### P06. 하루 5~10분씩 다시 공부하는 직장인 — 수진

- 목적: 짧게 배우고 정확히 이어서 공부한다.
- 여정: 홈 → 오늘 할 한 가지 → 중간 중단 → 다음 날 재접속 → 이어보기 → 오늘 마침.
- 예상 불편: 읽던 위치·답안 분실, 새로 들어올 때 다른 레슨 추천, 언제 그만해도 되는지 모름.
- 필요한 UX: 짧은 목표, 마지막 위치 저장, '여기까지 저장하고 나가기', 완료 후 명확한 종료 선택.
- 합격 기준: 중간에 닫고 다시 열어도 해당 레슨·읽던 위치·작성 답안을 복원한다. 예상 시간과 실제 공부 시간을 구분한다.

### P07. 이동 중 휴대전화로 학습하는 사용자 — 현우

- 목적: 지하철에서 설명을 읽고 문제를 푼다.
- 여정: 모바일 진입 → 레슨 → 키보드로 답안 입력 → 통신 끊김 → 재접속 → 제출 결과 확인.
- 예상 불편: 사이드바가 첫 화면을 가림, 키보드가 제출 버튼을 덮음, 수식 가로 넘침, 느린 요청을 여러 번 제출.
- 필요한 UX: 모바일 기본 접힘 메뉴, 터치하기 쉬운 버튼, 수식 영역의 적절한 스크롤, 요청 상태, 입력 보존·재시도.
- 합격 기준: 360px·390px 화면에서 핵심 버튼에 접근할 수 있다. 재시도로 답안이나 완료 기록이 중복되지 않는다. 실제 휴대전화에서도 확인한다.

### P08. 큰 글씨와 키보드 탐색을 사용하는 학습자 — 은정

- 목적: 화면을 확대하고 키보드로 안정적으로 공부한다.
- 여정: 확대 → Tab으로 레슨 선택 → 대화창 → 질문 → 닫기 → 원래 위치에서 계속 학습.
- 예상 불편: 이름 없는 아이콘, 마우스로만 클릭 가능한 행, 모달 뒤로 이동하는 포커스, 잘린 긴 문장, 색만으로 구분한 답안.
- 필요한 UX: 의미 있는 버튼 이름, 입력창 라벨, 키보드 조작, 모달 포커스 유지·복귀, 확대 가능한 배치, 텍스트로 된 결과 상태.
- 합격 기준: 마우스 없이 열기·입력·제출·닫기·완료를 수행한다. 200% 확대에서도 내용·버튼이 사라지지 않는다.

### P09. 공용 PC와 개인 휴대전화를 번갈아 쓰는 학습자 — 도윤

- 목적: 어느 기기에서든 자신의 기록만 이어서 본다.
- 여정: PC 로그인 → 문제·메모 → 로그아웃 → 다른 계정 로그인 → 휴대전화에서 자신의 계정 접속.
- 예상 불편: 로그인처럼 보여도 실제 인증 없음, 계정별 기록 혼합, 다른 기기에 기록 없음, 동시 편집 덮어쓰기.
- 필요한 UX: 실제 인증, 계정별 데이터 분리, 게스트 기록 이전 정책, 동기화 상태, 충돌 복구, 명확한 로그아웃.
- 합격 기준: A 계정의 기록이 B 계정에 보이지 않는다. A는 다른 기기에서 자신의 최근 기록을 다시 볼 수 있다. 동기화 실패를 저장 완료로 표시하지 않는다.

### P10. AI의 설명과 평가 근거를 확인하는 학습자 — 하린

- 목적: 잘못 배울 위험을 줄이고 실제 이해 정도를 판단한다.
- 여정: 설명 읽기 → 근거 확인 → 다른 형태의 정답 입력 → 판정 확인 → 재검토 요청 → 복습으로 이해 확인.
- 예상 불편: 0.5와 1/2를 다르게 채점, AI 실패를 실력 부족으로 기록, 고정된 'AI 진단', 완료만 눌러 숙련도 상승.
- 필요한 UX: 동치 답안 처리, 판정 보류·이의 제기, 생성/검수 상태, 점수 산정 설명, 학습 완료와 숙련도 분리.
- 합격 기준: 서비스 장애로 학습자의 오답 수가 늘지 않는다. 표시된 진단·추천은 실제 풀이 기록으로 설명 가능하다.

## 3. 처음부터 다시 방문할 때까지의 목표 여정

첫 방문에서는 '샘플 학습하기', 재방문에서는 '이어서 학습하기'를 대표 행동으로 삼는다. 진단·상세 목표·학습 도구는 필요한 시점에 제공한다.

| 단계 | 정상 흐름 | 함께 설계할 실패·분기 | 필수 UX와 통과 조건 |
|---|---|---|---|
| 1. 첫 방문 | 서비스 설명 → 샘플 시작 | 기록 없음, 기존 기록 있음, 로그인 없이 이용 | 샘플/개인 데이터 구분; 처음 할 일이 명확함 |
| 2. 로그인 | 방법 선택 → 인증 → 원래 위치로 복귀 | 취소, 인증 실패·만료, 팝업 차단, 중복 클릭 | 입력·학습 상태 유지; 실패 원인과 복구 방법 표시 |
| 3. 계정·기록 연결 | 게스트 기록을 계정으로 이전 | 기존 계정에도 기록 있음, 계정 전환, 동시 접속 | 합치기·유지 정책 명확; 다른 사람 기록은 노출 안 됨 |
| 4. 목표 설정 | 과목·목표 입력 → 권장 수준 | 목표가 막연함, 수준 모름, 설정 건너뛰기 | 예시·기본값·선택 진단; 설정을 나중에 변경 가능 |
| 5. 수준 진단 | 개념별 응답 → 추천과 이유 | 모름, 중단, 재진단, 일부만 틀림 | 추천 근거와 불확실성; 결과가 목표를 강제로 바꾸지 않음 |
| 6. 커리큘럼 | 생성 → 목차 검토 → 시작 | 지연, 실패, 빈 결과, 중복 주제, 생성 중 닫기 | 진행 상태·재시도; 새 결과가 나타나도 현재 학습을 빼앗지 않음 |
| 7. 홈·목차 | 마지막 레슨 또는 오늘 할 일 선택 | 여러 과목, 전부 완료, 검색 결과 없음 | 현재/다음 위치·총량·대안 행동; 브라우저 이동으로 복귀 가능 |
| 8. 레슨 | 목표 → 설명 → 예시 → 확인 문제 | 본문 오류, 생성 실패, 너무 어려움·쉬움, 콘텐츠 갱신 | 적절한 난이도 조절; 다른 주제 대체 금지; 오류 제보·재시도 |
| 9. 도움 요청 | 힌트/튜터 → 본문 복귀 | 여러 번 질문, 레슨 전환, 응답 실패 | 현재 문단과 대화 맥락 유지; 재질문 경로; 도움 내용 보관 범위 안내 |

## 5. 개선 순서와 운영 방법

1. 신뢰 기반: 실제 인증과 저장 범위, 개인/샘플 기록 분리, 채점 장애·콘텐츠 실패·저장 실패 처리.
2. 핵심 학습 한 바퀴: 시작 → 계획 확인 → 레슨 → 풀이 → 결과 → 종료 → 이어보기.
3. 학습 효과: 개념별 진단, 오답 재도전, 일관된 실력 지표, 실제 날짜 기반 복습 예약.
4. 사용 환경: 모바일·키보드·확대·느린 통신·공용 기기 문제를 각 단계와 함께 확인.
5. 확장: 실제 핵심 이용자 검증 후 언어 음성·코드 실행·다양한 리포트 필요성을 판단.

후속 구현을 진행할 경우에도 총괄은 요구사항과 완료 기준을 관리하고, Luna High 담당자에게 파일 소유 범위가 겹치지 않게 배정한다. 공통 App·타입·저장 구조 변경은 통합 담당 한 명이 맡는다. 각 담당자는 변경 목록·미해결 항목·사용자가 확인할 절차를 제출한다. '구현 완료'와 '사용자 검증 통과'는 별도로 기록한다.

향후 제품 지표는 첫 레슨 시작/완료 비율, 생성·채점 실패 후 복귀 비율, 중단 후 이어보기 성공, 오답 재도전 성공, 예정 복습 완료를 우선 본다. 현재 측정값이 있다고 가정하지 않는다. 오래 머무른 시간 자체를 학습 성공으로 해석하지 않는다.
