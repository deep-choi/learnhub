# 레슨 대화 흐름과 오른쪽 작업 패널 계획 (2026-10-02)

작성: UX/PM 탭. 구현은 coder 1(데이터·서버), coder 2(UI)가 나눠서 진행한다. 작업 브랜치는 `feat/chat-first-learning-coach`이고, 커밋은 UX/PM이 검증한 뒤 한다.

## 1. 사용자 요청

1. 레슨 화면 오른쪽에 있던 내용을 **AI 채팅 대화 안에서 단계별로 유도**하며 녹인다.
   - 지금 오른쪽에 있는 것: 미니 지도, "오늘은 여기까지 잘했어요" 마무리, 다음 학습 추천, "본문 학습을 모두 마치셨나요? 문제 풀기 / 충분히 학습했어요"
2. 오른쪽은 **옵시디언처럼 그래프 뷰나 메모장 같은 패널을 추가할 수 있는 작업 공간**으로 설계한다.

## 2. 레슨 = 단계별 대화

레슨 본문은 이미 단계(`content.steps`, 보통 4개: 개념 → 예시 → 해보기 → 정리)로 나뉘어 있다. 이 단계를 한 번에 다 보여주지 않고, 튜터가 대화로 하나씩 이끈다.

```
[LearnHub 튜터] 오늘은 '카메라 파지법'을 배워요. 4단계로 갈게요. (1/4)
               1. 안정적인 촬영을 위한 파지의 원리 …
               [이해했어요, 다음으로]  [더 쉽게 설명해 주세요]  [예시로 보여주세요]
[나]           이해했어요, 다음으로
[LearnHub 튜터] (2/4) 2. 스탠딩 포지션에서의 표준 파지 단계 …
 …
[LearnHub 튜터] (4/4) 정리 …
               잘 따라오셨어요. 이해했는지 짧게 확인해 볼까요?
               [확인 문제 풀기]  [괜찮아요, 넘어갈게요]
[LearnHub 튜터] (문제를 풀었다면 결과와 해설)
               이 레슨을 완료로 표시할게요. ✓
               다음엔 '선명한 상을 맺는 반셔터와 초점'을 배워볼까요? 방금 배운 파지법과 이어져요.
               [다음 레슨 시작]  [다른 걸 배울래요]  [오늘은 여기까지]
```

### 원칙

- **한 번에 한 단계씩:** 단계마다 진행 표시 `(n/전체)`를 붙이고, 빠른 답 칩으로 다음으로 넘어간다.
- **언제든 자유 질문:** 하단 입력창은 항상 열려 있다. 질문하면 튜터가 답한 뒤 "이어서 갈까요?" 칩으로 원래 단계로 돌아온다.
- **설명 깊이 칩:** "더 쉽게 / 정식 개념으로 / 예시로"는 하단 고정 칩 줄에서 빼고, 각 단계 메시지의 칩으로 넣는다.
- **문제는 선택:** 마지막 단계 뒤에 한 번 제안하고, 사용자가 원하면 대화 안에서 푼다. 언제든 "문제 내줘"라고 입력해도 된다.
- **완료:**
  - "확인 문제 풀기"를 끝내거나 "넘어갈게요"를 고르면 레슨을 완료로 기록한다. 기존 "충분히 학습했어요"를 대체한다.
  - 문제를 맞히면 개념 상태는 `verified`, 넘어가면 `learned`가 된다.
- **다음 학습 유도:** 완료 직후 같은 대화에서 추천을 이어 준다. 기존 `recommendNextSteps`와 next-nudge를 그대로 쓴다.
- **오늘은 여기까지:** 세션이 길면(기존 `wrap_up` 규칙) 추천 대신 마무리 메시지와 칩을 준다.
- **이미 진행한 레슨을 다시 열면:** 대화 기록과 현재 단계가 복원되어 이어서 진행한다. 완료한 레슨은 처음부터 다시 보기와 바로 질문하기를 고를 수 있다.
- **실기형(`practical`):** 확인 문제 대신 "해봤어요" 칩과 한 줄 회고를 대화 안에서 받는다.

## 3. 오른쪽 = 패널 작업 공간 (옵시디언 스타일)

```
┌─────────────────────────────┐
│ [그래프 뷰 ×] [메모 ×]  +   │  ← 탭, + 로 패널 추가
├─────────────────────────────┤
│                             │
│   (선택한 탭의 패널 내용)    │
│                             │
└─────────────────────────────┘
```

- **탭 방식:** 패널은 탭으로 열고, 각 탭에 닫기(×)가 있다. `+`를 누르면 추가할 패널 종류를 고른다.
- **첫 버전 패널 종류:**
  - **그래프 뷰:** 지금 레슨 개념 중심의 로컬 그래프다. 확대/축소, 노드 클릭 시 상세가 나오고, 전체 지도로 가는 링크가 있다. 옵시디언 그래프 뷰처럼 넉넉한 캔버스를 쓴다.
  - **메모:** 지금 레슨·개념에 연결된 메모장이다. 마크다운으로 편집하고 자동 저장하며, 계정 동기화된다. 개념 이름을 `[[개념]]`으로 쓰면 그 개념과 연결된다.
- **확장 가능한 구조:** 패널 종류는 레지스트리(종류 id, 제목, 아이콘, 렌더 함수)로 만든다. 나중에 목차, 오답 노트 같은 패널을 쉽게 추가할 수 있어야 한다.
- **레이아웃 기억:** 열린 탭과 선택 탭, 패널 폭은 이 기기에 기억한다 (localStorage, 기기별 편의).
- **조절과 모바일:** 패널 영역은 접을 수 있고, 데스크톱에서는 드래그로 폭을 조절한다. 모바일에서는 하단 시트나 전체 화면 오버레이로 연다.
- **기본 상태:** 레슨을 처음 열면 그래프 뷰 탭 하나만 열려 있다.
- **화면 범위:** 레슨 화면에 먼저 적용한다. 메인 대화 화면에는 지금 넣지 않는다.

### 메모와 그래프 연결

- 메모는 개념 노드에 붙는다. 그래프에서 메모가 있는 노드는 작은 표시를 보여준다.
- 노드 상세에서 "메모 열기"를 누르면 메모 탭이 열린다.
- 메모 안의 `[[개념]]` 링크는 그 개념과 연결된다. 그래프에 별도의 메모 노드를 그리지는 않는다. 그래프가 복잡해지지 않게 하기 위해서다.

## 4. 담당

### coder 1 — 데이터·서버

소유 파일: `src/types/*`, `src/domain/*`, `src/services/*`, `server.ts`, `server/*`, 관련 `tests/*`

1. **메모 데이터:**
   - `LearningNote { id, title, body(markdown), conceptId?, courseId?, lessonId?, links: conceptId[], createdAt, updatedAt }`
   - 저장 함수: `listNotes`, `getNotesForConcept`, `getNoteForLesson`, `saveNote`, `deleteNote`
   - `[[개념]]` 파싱 함수(이름을 개념 노드에 매칭)를 만든다.
   - 기존 `learnhub_note_` 저장소와 백업·동기화 경로를 재사용하거나 이전한다. 기존 메모가 사라지지 않게 하고, 크기 상한을 둔다.
2. **레슨 진행 상태:**
   - `LessonProgressState { lessonId, stepIndex, phase: 'steps' | 'check' | 'done', checkResult? }`를 레슨 단위로 저장하고 계정 동기화한다.
   - 다시 열 때 이어가기에 쓴다.
3. **완료 처리:** "넘어갈게요"는 `markLessonCompleted`로 `learned`, 문제 정답은 `verified`로 처리한다. 기존 함수로 되면 새로 만들지 않는다.
4. **그래프 표시용 조회:** 메모가 있는 개념 id 목록을 조회하는 함수를 만든다.
5. **테스트.**

### coder 2 — UI

소유 파일: `src/components/*`, `src/App.tsx`, `src/index.css`

1. `LearningConversationView`를 위 2절의 **단계별 대화**로 바꾼다.
   - 진행 표시, 단계별 칩, 자유 질문 뒤 복귀, 확인 문제 제안, 완료, 다음 학습 추천, 마무리를 모두 대화 메시지와 칩으로 처리한다.
   - 오른쪽에 있던 카드들은 없앤다.
2. 오른쪽 **패널 작업 공간**: 탭, `+` 추가 메뉴, 닫기, 패널 레지스트리, 그래프 뷰 패널, 메모 패널(마크다운 편집과 미리보기, 자동 저장, `[[개념]]` 링크), 접기, 폭 조절, 모바일 시트를 만든다.
3. 그래프에 메모 표시를 넣고, 노드 상세에 "메모 열기"를 추가한다.
4. 기존 흰 배경, 16px, 튜터 프로필 말풍선 기준을 유지한다.

### 공통 규칙

- coder 1이 먼저 타입과 함수 시그니처를 컴파일되는 상태로 만들고, coder 2는 그 전까지 mock으로 진행한다.
- 자기 소유가 아닌 파일은 수정하지 않는다. 필요한 변경은 UX/PM(learnhub-bb)에게 알린다.
- 커밋과 푸시는 하지 않는다. 끝나면 `npm run lint`와 `npm test` 결과를 UX/PM에게 보고한다.
