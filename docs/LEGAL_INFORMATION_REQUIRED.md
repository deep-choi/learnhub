# 이용약관·개인정보 처리방침 작성에 필요한 운영 정보

아래 값은 코드에서 추론하거나 임의로 만들 수 없는 서비스 운영자의 결정 사항이다. 값을 확정한 뒤 공개 약관/개인정보 처리방침 페이지를 만들고 회원가입 화면에 연결한다.

## 1. 운영자 정보

- 운영 주체의 법적 이름 또는 상호
- 대표자명(사업자인 경우)
- 사업자등록번호와 통신판매업 신고번호(해당하는 경우)
- 주소
- 고객 문의 이메일
- 개인정보 보호 문의 담당자와 이메일 또는 전화번호

## 2. 서비스 정책

- 서비스 이용 가능 최소 연령과 미성년자 정책
- 유료 기능 제공 여부, 결제·환불 정책
- 금지 행위와 계정 제한/해지 기준
- 서비스 변경·중단 시 고지 방식과 기간
- 준거법과 분쟁 관할

## 3. 개인정보 보유·삭제 정책

- 회원 이메일, 표시 이름, Firebase 사용자 UID의 보유 기간
- 과목·진도·퀴즈·노트·AI 대화 등 학습 기록의 보유 기간
- 콘텐츠 신고 기록의 보유 기간
- 회원 탈퇴 후 즉시 삭제 대상과 법적 의무로 별도 보관할 항목
- 휴면 계정 정책
- 백업에서 완전히 제거되기까지 걸리는 최대 기간

## 4. 외부 처리자와 국외 이전

현재 코드상 확인이 필요한 공급자는 다음과 같다. 실제 계약 계정의 법인명, 처리 국가/리전, 이전 일시·방법, 보유 기간을 운영 콘솔과 계약 문서에서 확인한다.

- Firebase Authentication/Firestore: 계정 인증, 학습 기록, 신고 및 사용량 저장
- Firebase Hosting/Cloud Functions: 웹 호스팅, API 처리, 운영 로그
- Google OAuth: Google 로그인 사용 시
- Google Gemini API: AI 학습 과정·레슨·평가 생성 시 전송되는 입력
- 이메일/SMTP 공급자: 가입 확인과 비밀번호 재설정 메일
- 배포·로그·분석 공급자: 실제 운영 환경에서 사용하는 경우

특히 AI 입력에 사용자가 개인정보나 민감정보를 넣을 수 있는지, 모델 학습에 사용되는지, 로그 보존 기간이 얼마인지를 실제 계약 조건과 맞춰 명시해야 한다.

## 5. 공개 전 연결 작업

1. 위 운영 값을 확정한다.
2. 변호사 또는 개인정보 담당자가 이용약관과 개인정보 처리방침을 검토한다.
3. 앱과 같은 공식 도메인에 두 문서를 공개한다.
4. 회원가입 화면에 문서 링크, 필수 동의 항목, 동의 버전을 추가한다.
5. DB에 사용자 ID, 약관 종류, 버전, 동의 시각을 저장하고 RLS를 적용한다.
6. 개정 시 재동의가 필요한 변경과 단순 고지 변경을 구분한다.

실제 URL과 문서 버전이 확정되기 전에는 빈 링크나 가짜 동의 문구를 출시하지 않는다.
